# owl — P(−1) Audit, Hardening and Repair

- **Date:** 2026-10-31
- **Version audited:** 1.5.2 (commit `c35d05d`)
- **Version shipping the repairs:** 1.5.3
- **Source under review:** `src/main.cyr`, `src/escape.cyr`, `src/lang.cyr`,
  `src/theme.cyr`, `src/config.cyr`, `src/pager.cyr`, `src/vcs.cyr` (4,383
  lines), plus `tests/` and `scripts/smoke.sh`. `src/fetch.cyr` is not built
  and is out of scope; it gets its own audit before it is ever wired in.
- **Excluded from scope:** vendored `lib/`: the cyrius stdlib (6.7.18),
  vyakarana 2.10.0 and sit 1.13.0's read bundle. Each is audited by its own
  project. owl's posture depends on their correctness, so a defect rooted
  there is filed as INFO with the upstream owner named, not repaired locally.
- **Previous audit:** [`2026-08-22-audit.md`](2026-08-22-audit.md) (1.4.6,
  FINDING-006 – 013). Everything since then is in scope:
  - 1.4.7 added `--format=ndjson`, `--follow` and `src/escape.cyr`;
  - 1.4.8 – 1.5.1 were four toolchain and dependency bumps;
  - 1.5.1 wired three grammars, and 1.5.2 wired markdown.
- **Methodology:** five independent reviews, one per area:
  - render paths and the escape classifier;
  - parsers of untrusted or user input (config, theme, language, CLI);
  - processes, file I/O, the pager and signals;
  - the in-process VCS read path against hostile repositories;
  - memory, resource bounds, performance and test coverage.

  Each review ran against the shipped 1.5.2 binaries and had to bring a
  working repro for every candidate. Every candidate was then reproduced
  again on a separate copy before it was accepted. Findings that more than
  one review reached independently are noted; nine were. Each repair has a
  smoke gate that was run against 1.5.2 and fails there. Overflows invisible
  from outside the process were proven with the poisoned allocator
  (`cyrius build -D CYRIUS_POISON`, exit 86 on a redzone write).

## Findings

### FINDING-014 — Escape stripping turned off whenever colour was off — **HIGH**

`_strip_active()`'s automatic mode returned "do not strip" whenever
`g_want_color` was 0. Colour is off under `NO_COLOR` (a common, standard
setting), under `--color=never`, and with `-n` on a pipe, yet in all three
owl still draws the decorated frame for a human. Every file-origin escape
went straight to the terminal: OSC 52 clipboard writes, title sets and
reports, screen clears. The same was true of `--follow`, which never pages.
This re-opens FINDING-001 under a documented configuration, and contradicts
both `--help` ("strip in decorated mode") and the 1.4.6 report, whose
INFO-002 text argued that a truncated environment could only fail to *enable*
`NO_COLOR`, "never toward passing file-origin escapes through". Honouring
`NO_COLOR` did exactly that.

**Repro:** `printf 'hello\n\033]52;c;cHduZWQ=\007world\n' > e.txt; NO_COLOR=1
script -qc "owl --paging=never e.txt" /dev/null | cat -v` shows
`2 │ ^[]52;c;cHduZWQ=^Gworld`. The default `less -RFX` pager drops these
sequences, so the exposure was `--paging=never`, a non-less pager, and every
`-f` session. Found by two reviews independently.

**Fix:** stripping follows the frame, not the colour. Any decorated or
coloured render strips; only the undecorated, uncoloured stream (piped
output) passes through, cat-like by contract. **Gate:** `-n --color=never`
piped, plus `NO_COLOR` and `--color=never` on a TTY: zero ESC bytes, and the
content present.

### FINDING-015 — The header wrote the file name raw — **MEDIUM**

`emit_header` wrote `path` to stdout unfiltered. Every stderr echo has gone
through `eprint_sanitized` since FINDING-002, but the `File:` line is
stdout, and it is on the default TTY path. A file name is argv, and so glob
expansion over a tree someone else made: `owl src/*` in a cloned repo, where
git allows ESC and BEL in names. Found by four reviews.

**Repro:** a file named `x<ESC>]0;PWNED<BEL>.txt`; `owl -n x*` prints
`File: x^[]0;PWNED^G.txt`. **Fix:** `out_write_sanitized` (C0 and DEL become
`?`; UTF-8 passes). **Gate:** zero control bytes in the header, and
`x?]0;PWNED?.txt`.

### FINDING-016 — Stdin ignored `--format=ndjson` and `--hex` — **MEDIUM**

`render_fd` had neither branch. `owl --format=ndjson -` wrote the input
through unchanged, exit 0, so a line of the input that happens to be JSON
reached the consumer as a token record. That is precisely the forgery
`_ndjson_escape`'s own comment says owl must prevent. Without `--language`
it succeeded instead of failing with "needs a grammar". `--hex -` printed
raw bytes. Found by two reviews.

**Fix:** stdin routes through `_render_ndjson` and `_hex_dump_fd` exactly as
a file does. **Gate:** real records (and a forged line never echoed), a
non-zero exit without a grammar, and a hex dump for `--hex -`.

### FINDING-017 — Heap overflow building the user-grammar path — **MEDIUM**

`_owl_bootstrap_grammars` allocated a fixed 1024-byte path buffer and
`_owl_load_grammar` copied `<user dir><name>` into it with no length check.
The user dir is `$XDG_CONFIG_HOME/owl/grammars/` or
`$HOME/.config/owl/grammars/`, of unbounded length. It is reached by any
highlighted file, including the default `owl FILE` on a TTY. This is
FINDING-007's class at a sibling call site that fix did not reach. As with
007, the shipped binary shows nothing: the bytes landed in dead heap. Found
by three reviews.

**Repro:** a poisoned build exits 86 ("redzone overwrite — alloc block …
(1024 bytes)") at exactly `HOME` length 986, against 985 clean. **Fix:** the
directory is joined into an allocation sized from its length, refused past
4,096 bytes, and probed as a directory (`O_DIRECTORY | O_NONBLOCK`, so a FIFO
cannot block); the path buffer is sized for the longest directory. The two
49-name grammar lists collapsed into one loop over the language table, the
list whose drift caused 1.5.2's markdown gap. A dead allocation
(`_join_user_grammars`) is gone. **Gate:** long `HOME` / `XDG_CONFIG_HOME`
on the highlight path under `OWL_POISON_BIN` (NOTE-skips without one).

### FINDING-018 — An input of exactly 16 MiB was tokenized for 64 KiB — **MEDIUM**

`HIGHLIGHT_MAX` equalled vyakarana's `VYK_STREAM_CAP` (16 MiB), but a
stream holding `len` bytes needs `len + n + 1`. At exactly 16 MiB the second
feed failed with `VYK_ERR_OVERFLOW`, and all five call sites ignored the
result. `owl --format=ndjson` on a 16,777,216-byte file exited 0 with 53,620
records covering 65,536 bytes; at 16,777,215 bytes, 13.7 million records
reached EOF. A file padded to exactly 16 MiB therefore hid everything past
64 KiB from an ndjson consumer, as the "truncated stream that still looks
well-formed" the code's own comment forbids. The viewer coloured only the
first 73 KB, without a notice.

**Fix:** `HIGHLIGHT_MAX` is the stream's real capacity (16,777,215), every
feed is checked (a refused feed is an overflow), and the three copies of the
slurp collapsed into one `_hl_slurp`. A regular file known to be over the cap
is refused before it is tokenized (`_fd_size`), which saves ~2 s at 16 MiB.
**Gate:** a 16 MiB ndjson input exits non-zero with "too large".

### FINDING-019 — An ancestor FIFO hung repo discovery — **MEDIUM**

`_vcs_probe_repo` tested `.git/HEAD` / `.sit/HEAD` with `file_exists`, which
`open()`s the path, at every ancestor of the viewed file. A FIFO named
`.git/HEAD` anywhere above it blocked the open forever, before anything was
rendered, even with `-p --diff`. sit's own probe refuses FIFOs.

**Fix:** the probe uses lstat/stat only, reads the mode through `STAT_MODE`,
and accepts a root only where a real repo has a regular-file `HEAD`. A FIFO,
socket or device `HEAD` is "no repo here", and the walk continues (sit's
rule). **Gate:** a FIFO `.git/HEAD` ancestor under `timeout`: owl exits 0.

### FINDING-020 — VCS memory was unbounded before the ceiling — **MEDIUM**

FINDING-012's `VCS_MAX_LINES` (16,777,216) bounded the marker table, but it
was checked *after* `sit_diff_path`, by which point sit had split, diffed and
annotated every line at ~155 bytes each on the never-freed heap. A 16 MB
file of newlines with a one-byte edit cost 2.54 GB and 3 s to show five
lines; under a 1 GB limit owl crashed. `vcs_enabled()` also returned 1 for
`-p --diff`, so plain mode paid the whole cost and threw the result away.

**Fix:** before sit is called, one lstat gives the type and size; files over
8 MiB are skipped, and a bounded count skips files over 524,288 lines. The
worst case is now ~160 MB, against 2.5 GB. `VCS_MAX_LINES` is lowered to
match and stays as the second check. `-p` skips VCS, except with
`--line-range`, the one plain path where `--diff` filters. Gutter mode skips
silently; `--diff` says "file too large to diff". The trade-off: files just
over 8 MiB (sqlite3.c, ~9 MB) lose their markers. The HEAD-side blob is
bounded only by sit's 16 MiB inflate cap (upstream). **Gates:** `--diff` of
1 MiB of newlines under a 128 MB address-space limit; `-p --diff` never
consults VCS.

### FINDING-021 — Stdout write errors were ignored — **MEDIUM**

Every output byte was its own `write(2)`, and no result was checked.
`owl f > /dev/full` and `owl f >&-` exited 0. With SIGPIPE ignored, which is
inherited from Python children and from systemd's `IgnoreSIGPIPE=yes`, owl
spun at 100% CPU forever once its reader quit, leaving `less` a zombie.
Design-spec §9 asks for exit 3.

**Fix:** a new module, `src/out.cyr`, buffers all output (64 KiB on the heap;
writes of 4 KiB or more go straight out). It loops on short writes and
EINTR, exits 3 silently on EPIPE, and reports any other error ("No space
left on device", "stdout is closed") before exiting 3. Flushes happen before
anything reaches stderr, before the pager pipe is closed, before `--follow`
sleeps, after each file, and at exit. **Gates:** `/dev/full` exit 3 with a
message; a closed stdout exit 3; SIGPIPE ignored ends with 3, not
`timeout`'s 124.

### FINDING-022 — Memory grew with every highlighted file — **MEDIUM**

Each file allocated its own read buffers (128 KiB, even with `-p`), a fresh
16 MiB+1 slurp buffer and a fresh tokenbuf, none ever freed. 60 highlighted
92 KB files peaked at 238 MB; `owl src/*` on a terminal, the default mode,
could run out of memory. Under an address-space limit highlighting quietly
stopped partway (16 of 40 files at 300 MB), and a failed allocation surfaced
as a misleading "read error". Found by two reviews.

**Fix:** the slurp buffer, both read buffers and the tokenbuf are allocated
once and reused (uses are sequential). 60 files now peak at 62.5 MB. The
remaining ~0.8 MB per file is vyakarana's stream state (INFO-009). **Gate:**
40 highlighted files under a 300 MB address-space limit: all 40 coloured.

### FINDING-023 — The gutter wrote below its stack buffer — **MEDIUM**

`emit_lineno` filled `pbuf[8]` downward from index 5 with no lower bound.
From line 1,000,000 each extra digit was stored below the buffer, an
out-of-bounds stack write whose length is chosen by the file's line count.
In the 1.5.2 builds the stray byte landed in a dead frame slot. An identical
function compiled with its counter on the stack ran away and SIGSEGVed, so
the harmlessness was the compiler's layout, not the code's. The gutter showed
`000000` for line 1,000,000. Found by two reviews.

**Fix:** a 32-byte buffer (any i64), right-aligned in at least six columns;
a 7-digit number prints whole and widens the gutter by one column for those
lines. **Gate:** line 1,000,000 renders as `1000000`.

### FINDING-024 — Flags were applied in the order files were rendered — **LOW**

`main()` parsed and rendered in one loop, resolving the mode and starting the
pager at the first file:
- `owl a.c -p b.c` highlighted b.c, so `-p` was no longer cat-identical;
- `--color=never` after a file was ignored;
- `owl FILE --bogus` rendered FILE, then exited 2, leaving the pager
  orphaned on the TTY;
- `owl missing.txt -V` discarded the failure.

**Fix:** two passes, parse and validate everything first, then render.
`--follow` now requires exactly one file. **Gates:** `-p` after a file makes
the run cat-identical; `FILE --bogus` prints nothing and exits 2; `-f a b`
exits 2.

### FINDING-025 — Pager lifecycle — **LOW**

- **Ctrl-C** (and early exits) left `less` running with PPID 1. owl now
  ignores SIGINT while the pager owns the terminal (the pager keeps the
  default), and ends when the pager closes the pipe; early exits can no
  longer follow a started pager (FINDING-024).
- **With owl's fd 0 closed,** `pipe()` returned 0 as the read end, and the
  child's `dup2(0, 0); close(0)` closed the pager's input. The dup is now
  skipped when it is already fd 0.
- **The environment was read from a 16 KB `/proc/self/environ` buffer**
  with a 255-entry cap, so a large environment lost TERM, PATH and LANG.
  It is now built from the stdlib's `env_block`, sized to the real
  environment.
- **A bare `PAGER=less`** showed raw `ESC[…` and paged two-line files.
  `LESS=FRX` is now supplied when `LESS` is unset, as git does.

**Gates:** fd 0 closed (pager receives input), `LESS` unset (pager sees
`FRX`), and a 300-variable environment (pager sees TERM), all via
`script(1)`.

### FINDING-026 — The user-theme name dangled into a dead stack frame — **LOW**

`_cfg_apply` passed `&vbuf`, its stack buffer, to `theme_index`, and
`_user_theme_load_by_name` stored the pointer. The next config line reused
the frame, so after `theme = mytheme` then `tabs = 4`, a CLI
`--theme=mytheme` was rejected while `--theme=4` was accepted. With one
user-theme slot, a CLI `--theme=<other user theme>` could not override the
config either, contradicting `--help`. **Fix:** the name is copied to the
heap, and a later load replaces the slot (a failed load leaves it as it
was). **Gates:** both forms.

### FINDING-027 — `--line-range` zero and overflow — **LOW**

`0`, `0:` and `:0` meant "unset" and printed everything; 2^64+1 wrapped to
line 1 and 2^63 to the whole file (FINDING-010's lesson, again). **Fix:** an
explicit 0 is invalid (lines are 1-indexed) and each side is capped at 18
digits before accumulating. **Gate:** seven bad forms exit 2; `3:4` still
works.

### FINDING-028 — The overflow probe byte was dropped — **LOW**

At the highlight cap, one more byte was read to decide "too large", into a
throwaway local, then the plain fallback rendered without it. **Fix:** the
probe reads into the slurp buffer, which has room for it. **Gate:** a stdin
input over the cap comes out byte for byte.

### FINDING-029 — Config and theme files silently truncated at 8 KB — **LOW**

Lines past byte 8,192 were dropped and a line straddling the limit was
applied cut (`tabs = 64` became `tabs = 6`). **Fix:** a shared reader,
`cfg_read_regular`, reads `cap + 1` bytes with a probe that tells "exactly
full" from "more follows", never applies an unterminated tail, and warns
once: `owl: <path>: larger than 8192 bytes; lines past the limit ignored`.
**Gates:** config and theme.

### FINDING-030 — `ext.<X>` overrides — **LOW**

The stored extension kept its case while the path side was lowercased, so
`ext.CONF = shell` never matched. A repeated extension was first-wins, unlike
every other key. The 17th entry reported "bad value". **Fix:** stored
lowercased with a leading dot; re-registering replaces in place (no slot
used); a distinct `too many ext overrides (max 16)`. **Gates:** all three.

### FINDING-031 — Theme hardening bundle — **LOW**

- **Integers wrapped i64.** `18446744073709551716` was accepted as 100.
  Values are now refused past three digits, before accumulating.
- **Theme names were not confined to the themes directory.**
  `--theme=../../../x` loaded `$XDG/../x.cyml`. Names with `/`, empty, `.`,
  `..` or over 250 bytes are now refused.
- **Config and theme files were opened whatever their type.** A FIFO hung
  even `owl --version`, and `OWL_CONFIG=/dev/stdin` consumed piped input.
  Only a regular file is now read (stat before open; `/dev/null` still means
  "no config").
- **A NUL inside a config value silently cut it** (`tabs = 8<NUL>junk`
  applied 8). It is now "bad value"; the parser fuzz model found this one.

**Gates:** one per item.

### FINDING-032 — Wrong and missing error messages — **LOW**

EACCES, ENOTDIR, ELOOP, ENXIO and EMFILE all read "No such file or
directory"; a directory read "read error"; `owl - < dir` exited 4 silently.
**Fix:** `_errno_msg` maps the errno; a failure nothing explained is
reported, with stdin shown as `<stdin>`. **Gates:** a directory, ENOENT,
EACCES (skipped as root), and stdin from a directory.

### FINDING-033 — CRLF and tab shebangs — **LOW**

`#!/bin/sh\r\n` and `#!/usr/bin/env<TAB>python3` did not route. **Fix:** the
shebang copy stops at CR and treats TAB as a space (and no longer relies on
`break` in a `while` with declarations). **Gates:** both.

### FINDING-034 — `--follow` and truncation — **LOW**

After `: > log` (logrotate copytruncate) owl went silent and later printed a
torn fragment; with several files only the first was ever shown, and `-f -`
was silently not followed. **Fix:** when the size drops below the read
offset, owl rewinds, says `file truncated`, and resets the escape state;
`--follow` takes exactly one file (FINDING-024). **Gate:** lines appended
after a truncation are shown, with the notice.

### FINDING-035 — VCS markers for the wrong file — **LOW**

- **(a) A clean, committed symlink showed `~` on every line.** sit diffed
  the link blob against the target's content. Symlinks now get no markers.
- **(b) A `.git` that is a file was not a repo boundary.** This is the
  `gitdir:` file of submodules and `git worktree add`, so the walk reached
  the superproject and every line showed `+`. A `.git` file now stops the
  walk with no markers.
- **(c) Files inside `.git/` or `.sit/` showed all `+`.** They are now
  skipped.
- **(d) `..` was normalised lexically.** `R/lnk/../f.txt`, with `lnk` a
  symlink, displayed `X/f.txt` while the gutter showed `R/f.txt`'s changes.
  A `..` that would cross a symlink now skips markers. This works the same
  on Linux and agnos, whereas resolving through `/proc` would not.

`--diff` names each skip. **Gates:** one per case; a symlink-free `../f.txt`
still gets its markers.

### FINDING-036 — Render defects — **LOW**

- A highlighted `--line-range` emitted an empty SGR pair for every token
  before the range.
- A plain file after a highlighted one restored a stale colour on wrap
  continuation rows.
- A CRLF line of exactly the wrap width wrapped on its CR into a phantom
  `↪ ^M` row.
- With `-N`, continuation rows were padded to a gutter that was never
  subtracted from the budget (91 columns on an 80-column terminal).
- A file without a trailing newline had the bottom rule drawn onto its last
  line.

All five are fixed. **Gate:** no empty SGR pair outside `--line-range`; the
other four were verified by hand on a pseudo-TTY.

### FINDING-037 — ndjson and invalid UTF-8 — **LOW**

Bytes ≥ 0x80 were copied into JSON strings raw, so invalid UTF-8 produced
invalid JSON. **Fix:** each sequence is validated per RFC 3629 (overlongs,
surrogates, > U+10FFFF and sequences cut by a token boundary all rejected);
valid UTF-8 passes untouched, so the 1.4.7 round-trip guarantee holds, and
each invalid byte becomes U+FFFD. **Gate:** no raw invalid byte, U+FFFD
present, valid UTF-8 intact.

### FINDING-038 — An unreadable command line read as "no arguments" — **LOW**

The stdlib reads argv from `/proc/self/cmdline`. Without `/proc`, or with
fds exhausted, `args_init()` failed, its result was ignored, and owl read
stdin instead (and blocked forever on a socket). **Fix:**
`owl: cannot read the command line`, exit 2. **Gate:** `ulimit -n 3`.

### FINDING-039 — Test gaps — **LOW**

- **Two vacuous gates.** smoke's FINDING-001 gate counted ESC bytes and
  passed for a binary that printed nothing; it now also asserts the exact
  text (`abcdefg`). FINDING-008's gate checked only an upper bound on SGR
  length; it now also requires that colour was emitted.
- **No precision invariant.** Two classifier mutants passed all five
  invariants of `tests/owl.fcyr`, and smoke, while hiding the rest of every
  line: a CSI final byte that no longer terminates, and BEL / ST no longer
  ending a string. Invariant 6 ("precision": a well-formed sequence is
  suppressed whole and the text after it emitted exactly) fails on both,
  verified by applying each mutant; so does the rewritten smoke gate.
- **No config or theme harness** (1.4.6's open follow-up).
  `tests/owl_config.fcyr` asserts six invariants against independent
  reference models: outcome codes, the exact setter values, theme slot
  bounds, name confinement, the ext table, last-wins ordering, and the
  reader's boundaries. It caught 11 planted mutations.
- **No ndjson or `--follow` gates.** Both now have gates, through
  FINDING-016, 018, 034 and 037.

## Informational

- **INFO-004 (sit) — tree-bomb `.git`, impact HIGH.** `sit_diff_path`
  flattens the whole HEAD tree on every call. `_TREE_MAX_NODES` bounds
  entries, not bytes, so a 208 KB `.git` (a 20-deep chain of 255-byte names
  over 1,000-blob leaves) costs 644 MB at N=100, 2.56 GB at N=400, and "sit:
  out of memory" before the file is shown at N=2000. In a real 100K-file
  repo it costs ~34 MB and 0.34 s per viewed file. The repair belongs in
  sit: resolve one path by walking its own components. owl's only
  containment would be running VCS in a forked, rlimited child, which is a
  design change. Not taken.
- **INFO-005 (sit).** If any process holds `LOCK_EX` on
  `.sit/objects.flock`, the read API waits forever ("sit: waiting for `sit
  gc` …"). flock needs only read access, so another user of a shared repo
  can do it. Viewing also creates the lock file when it is missing. owl
  would pass a zero wait if sit exposed one.
- **INFO-006 (sit).** A HEAD side sit cannot read (over 16 MiB, corrupt, a
  huge pack dir) is treated as absent, so every line is marked `+`. A diff
  that hits sit's Myers cap returns "unchanged", so `--diff` prints nothing
  with exit 0. Distinct statuses would let owl warn.
- **INFO-007 (sit).** `.gitattributes` `eol` / `text` / `filter` are not
  applied: a `text eol=crlf` file shows `~` on every line while `git status`
  is clean.
- **INFO-008 (sit).** `commit_tree_hex` dangles in `dist/sit-read.cyr` since
  sit 1.7.6. `cmd_show`, compiled into the read profile, calls it from
  `src/history.cyr`, which the profile omits. It is unreachable for owl
  (cyrius refuses to emit a reachable undefined function) and absent from
  ADR 0013's list.
- **INFO-009 (vyakarana).** Each stream keeps its own copy of the input, and
  on the never-freed heap that copy is not reclaimed between files: ~0.8 MB
  per 92 KB highlighted file after FINDING-022. Resident memory for one
  highlighted file is ~13× its size, not the ~4× CLAUDE.md claimed
  (corrected).
- **INFO-010 (cyrius).** argv comes from `/proc/self/cmdline` rather than
  the initial stack (FINDING-038 is owl's half).
- **INFO-011 — accepted.** CR and BS pass through on the stripped path, so a
  file can overwrite its own gutter on screen. This is the hidden-content
  class `cat` and `bat` share; `-A` shows them. Revisit if owl grows a
  "show CR mid-line" mode.
- **INFO-012 — open decision.** Piped output (without `-p`) expands tabs to
  `--tabs`; design-spec §4.2 originally said piped bytes pass "essentially
  unchanged", and smoke pins the expansion. The spec now documents the
  behaviour; keeping literal tabs when piped is a user decision for a later
  release.
- **INFO-013 — 1.6.x.** The `# ` content sniff tags `.bashrc` and
  `.gitignore` as markdown. vyakarana's registry routing (roadmap 1.6.x)
  routes those by declared filename.
- **INFO-014 — 1.6.x.** No `--` end-of-options marker; part of the cmdit
  adoption.
- **INFO-015 — doc corrected.** design-spec §3.3 / §3.4 documented `-P`,
  space-separated values, a `--style` comma list and `OWL_THEME`, none of
  which exist. The spec now matches `--help`, which gains the `ext.<ext>`
  key.

## Discarded at the repro stage

- **Shebang boundary underflow** (`while (si <= sblen - h_len)`), carried
  over from the 1.4.6 discards. Still no repro: a hint longer than the line,
  a bare `#!` and an empty shebang are all handled.
- **Short writes / EAGAIN on an O_NONBLOCK stdout.** No short write could be
  produced without a signal handler. It is moot now: `out_flush` loops.
- **A cross-user ancestor repo** (another user's `/tmp/.git`). The walk does
  reach ancestors and has no uid check, but no second uid was available to
  demonstrate a planted repo. Recorded as a hardening idea, not a finding.
- **Visible corruption from FINDING-017 on stock builds.** The write is
  proven by the poisoned allocator and a canary, but output was unchanged
  at every length tried. It is still a finding.

## Performance

Measured on the shipped `CYRIUS_DCE=1` binaries, output to `/dev/null`,
median of seven runs (1.5.2 → 1.5.3):

| Mode | 1.5.2 | 1.5.3 | |
|------|------:|------:|--|
| piped, default (7.3 MB) | 3.01 s | 0.16 s | 18.8× |
| `-n --color=never` (7.3 MB) | 3.34 s | 0.23 s | 14.4× |
| highlighted `--color=always` (7.3 MB) | 6.20 s | 1.51 s | 4.1× |
| `--format=ndjson` (1 MB) | 1.47 s | 0.24 s | 6.1× |
| `-p` (73 MB) | 10.2 ms | 11.2 ms | within noise |
| 60 highlighted 92 KB files, peak RSS | 238.4 MB | 62.5 MB | 3.8× less |

Where the time went:
- **Output buffering** (`src/out.cyr`): one `write(2)` per byte became one
  per 64 KiB.
- **A per-render kind→colour table:** `theme_token_color` had run
  `kind_name` plus up to seven `streq` per highlighted byte.
- **The overflow pre-check:** a regular file known to be over the highlight
  cap is not tokenized first.
- **The user-overlay probe:** an absent overlay directory is now probed
  once, rather than costing 49 failed opens on every first highlight.

A first cut of the buffer copied `-p`'s 64 KiB chunks into it, which made
plain mode ~6× slower (16.7 ms → 111 ms on 73 MB, still byte-identical). The
benchmark caught it, not a gate, and large writes now bypass the buffer.
